# Linux 构建：另一台 Linux 构建机

**LF 2026-11-15 要求：本应用以后的 Linux 构建都在 另一台 Linux 构建机（主机名见私有运维记录）做，不再用 LF 的 PC 构建生产版。** 生产服务器只运行部署好的二进制；PC 的 Windows `.exe` 只用于本地界面验证。

本机实测（2026-11-15）：Debian 13 x86_64，2 核，约 3.9 GiB 内存、无 swap、系统盘 39 GiB 可用，Docker 29.9.2。生产服务只在运行机；该机器只是构建机，不跑网关、不保存生产数据库或密钥。

## 构建目录与输入

- 构建目录：`/opt/build/gist-gateway/`，源码在 `source/`，产物在 `source/target/release/gist-gateway`。
- 只上传通用构建输入：`Cargo.toml`、`Cargo.lock`、`migrations/`、`src/`、`templates/`、`static/`。不传 `var/`、`.tools/`、`master.key`、SQLite、正式域名或凭据。
- 使用固定镜像 `rust:1-slim-bookworm`；首次拉取后记录实际镜像摘要。本机用 `cargo test --release --locked` 与 `cargo build --release --locked`。
- 构建容器限 1.5 GiB 内存、**禁用 swap**（主机本身无 swap）、1 CPU、`CARGO_BUILD_JOBS=2`、`no-new-privileges`、`cap-drop=ALL`、有限进程数和日志。首次完整测试构建 4m00s、发布构建 2m04s（含首次依赖编译），比旧构建环境的单核/512 MiB 配置宽裕；这不是增量构建时间承诺。
- 首次实机结果（2026-11-15）：Rust 1.100.0，26 项发布测试通过；产物 5,215,120 字节，SHA-256 `6864ec51ef65db881c791d0b6f7d779ec3634f513866ffd8ce9b239f92ddf9c4`，与当前运行机已有的同源码二进制一致，本次未重启生产服务。镜像摘要 `rust@sha256:7c7d4eb4d05b7781187a327809466cfddf29753f6defdc3d19a0e291951b7a37`，构建目录约 897 MiB。
- 源码压缩包先写独立临时文件，解压到干净目录；执行构建脚本时从仓库目录传绝对路径，避免把脚本放进不可信压缩包目录。

## 推荐流程

1. 本机完成格式、Clippy、测试和 Windows 构建后，把源码打包传到构建机；逐文件 SHA-256 核对上传内容。
2. 在构建机的受限容器中执行发布测试和构建，记录 Rust 版本、镜像摘要、产物字节数及 SHA-256。
3. 只将构建机产出的 Linux 可执行文件和校验值传到运行机的独立候选位置；在运行机上核对哈希、备份旧二进制、安装并重启 systemd `gist-gateway`。
4. 运行生产 HTTPS 验收；构建机的目录和镜像保留以便增量编译，不向公网开放端口、不在构建机起常驻服务。
5. 源码和通用文档推送到源码仓库；服务器地址、IP 白名单、正式口令和备份路径不写入源码仓库。
