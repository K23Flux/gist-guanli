# Gist 网关

一个 Rust 编写的轻量订阅分发网站：导入现有 Gist，为同一份文件生成多条可单独撤销的分享链接。配置内容继续在 Gist 维护，网关直接返回正文，不转换节点或客户端规则，不跳转到原始地址。

```text
客户端 → /s/自定义后缀/独立随机令牌/loon.conf → 验证分享状态 → 获取或读取 Gist 缓存 → 返回正文
```

## 状态

本地实现及 Linux 生产部署验收已完成（2026-11-15）。受控 Debian 13 主机采用原生二进制、独立 systemd 服务及 HTTPS 反代；正式初始化未复用演示数据。原订阅、客户端、现有 Gist 和同步工作流未改，验收链接已撤销。实际结果及未测范围见 [VALIDATION.md](VALIDATION.md)，systemd 运维参考见 [deploy/README.md](deploy/README.md)。手机界面见 [预览图](docs/mobile-preview.jpg)。

## 功能

- 导入 Gist 页面或 raw 地址；多个文件需要明确选择；raw 批量导入每批最多 50 条。
- 固定版本 raw 地址必须单独确认改为跟随最新；批量导入拒绝固定版本地址。
- 来源与分享分离：同一文件可有多条分享链接，各自命名、暂停、恢复、到期、重置或删除。新建时默认沿用来源文件名、永久有效，需要时再改名称或到期时间；分享绑定在创建它的来源上，编辑时不再选择来源。
- 更换来源不改变分享地址；删除仍被引用的来源会被拒绝。
- 中文管理页、搜索、来源筛选、本地二维码和临时查看/复制完整链接。
- 管理员本地初始化、Argon2id 口令校验、12 小时会话、CSRF、同源检查与登录限速；没有公开注册/安装入口。
- 分享令牌来自 32 字节安全随机数，使用摘要验证；另加密保存以便管理员再次复制。源地址和订阅内容不会写进访问日志。

朋友不需要登录。自定义文件名只影响地址中的名称，不会把 Loon 内容变成 Clash 格式；不同格式应各自绑定对应的 Gist 文件。

## 低内存默认值

| 项目 | 默认值 |
| --- | --- |
| 正文缓存 | 最多 4 MiB、128 条，按来源共享、按需刷新 |
| 缓存有效期 | 60 秒，管理页可调 10～3600 秒 |
| 上游并发 | 最多 2 个，等待及读取总超时 15 秒 |
| 单文件 | 解压后的正文最多 2 MiB |
| 同时分发 | 最多 8 个响应，超量返回 503 |
| SQLite | 2 个连接，每连接约 512 KiB 页缓存，WAL |
| 访问统计 | 内存聚合，每 30 秒写入；异常退出可能少计 |
| 来源/分享数量 | 最多 512 个来源、2048 条分享 |

实际内存取决于平台、TLS、缓存和正在传输的文件。Argon2id 单次约使用 19 MiB 工作内存，认证串行处理；不为压低数字削弱口令哈希。容器示例预留 128 MiB，必须结合目标机实测，不把该额度当作运行占用。

## 本地构建与启动

需要 Rust stable、系统 C 编译器（SQLite 与 TLS 依赖的构建需要）。应用没有 Node 前端构建步骤，HTML/CSS/JS 随二进制内置。`Cargo.lock` 固定依赖。

在本目录构建：

```bash
cargo build --locked --release
```

初始化本地测试数据（交互输入管理员口令，至少 12 个字符）：

```bash
./target/release/gist-gateway --data-dir ./var init --dev --public-url http://localhost:4387
```

本机运行：

```bash
./target/release/gist-gateway --data-dir ./var serve --dev --bind 127.0.0.1:4387
```

访问 `http://localhost:4387/admin`。请保持与初始化时的主机名一致，不能把 localhost 和 127.0.0.1 混用后再提交操作。同源校验使用数据库中设置的对外地址，不信任请求 Host 或任意转发头。

`--secret-stdin` 可从标准输入读取初始化口令，供本地自动化使用；不要把真实口令写在命令参数、脚本源码或终端历史中。Windows 产物扩展名为 `.exe`。本次隔离安装的工具链位于忽略目录 `.tools/`，不纳入仓库。

## 生产部署

本次 Linux 部署采用 [systemd 服务参考](deploy/README.md)，已通过正式 HTTPS 与独立恢复验收。新的部署仍须核对正式地址、目标机器和现有反代访问策略。不要直接把本地开发数据作为正式数据使用。生产初始化使用 HTTPS 对外根地址且不带 `--dev`；生产会话 Cookie 自动启用 Secure。默认监听回环地址。`compose.example.yaml` 及完整运行时 Dockerfile 仍是未执行的参考：容器内监听全部接口，但宿主端口只发布到 127.0.0.1。本次仅使用受限官方 Rust 构建容器，运行服务是宿主原生进程。

容器参考操作：

```bash
docker compose -f compose.example.yaml build
```

```bash
docker compose -f compose.example.yaml run --rm --no-deps gateway init --public-url https://sub.example.com
```

```bash
docker compose -f compose.example.yaml up -d
```

以上会创建本机容器/卷；添加示例文件不等于已经部署。Docker 初始卷须允许 UID 10001 读写 `/data`，不要将项目根目录挂到容器。已有部署的备份、校验与回滚在实际部署审核时另行完成。

### 反代和日志

- HTTPS 在可信反代终止；管理员页面及 `/api/admin/*` 可以再叠加已有来源白名单。
- `/s/*` 使用每条分享自己的令牌校验，不能为开放订阅而整体取消已有后台保护。
- **反代访问日志必须对 `/s/*` 隐藏整个 URI 或关闭该路径访问日志。** 分享令牌在路径里，应用不记录 URL 并不代表反代也不记录。
- 不缓存 `/s/*` 响应。应用返回 `Cache-Control: no-store`、`Referrer-Policy: no-referrer`；管理页不加载第三方资源。
- 不把管理员源信息或响应正文发送到外部监控、公共转换站、二维码接口或分析服务。

## 数据与恢复

数据目录包含 `gateway.sqlite`、SQLite 的 `-wal`/`-shm` 文件及独立的 `master.key`。目录按敏感数据处理；Unix 初始化设置受限权限，Windows 依赖当前用户目录 ACL。令牌摘要不用于恢复原令牌，复制功能需要原密钥。

**备份与恢复必须同时保留数据库和原 master.key。** 密钥另存受控备份，不随数据库公开或提交到 Git。文件丢失后不能重新生成密钥再宣称原链接可以恢复。

最简单的一致备份方式是先停止本应用，再复制整个数据目录并单独备份密钥；在线备份应使用 SQLite backup API/工具，不要在运行时只复制主 `.sqlite` 文件。恢复至独立测试目录，确认管理员登录、旧链接可复制、令牌轮换与到期行为，再切换生产。初始化命令拒绝覆盖已有密钥或数据库。

分享/来源数量和最后访问仅用于管理。计数代表服务端生成成功响应，不能证明客户端完整收取，也不是代理流量统计。不持久记录客户端 IP 和 User-Agent。

## 访问与故障行为

- 每次请求先验证数据库权限，再取缓存，发送前再以同一数据库快照核对令牌、状态、到期、路径、来源绑定及来源版本。
- 撤销提交后开始最终校验的请求被拒绝；此前已获授权或正在传输的响应可能完成。已下载的配置无法收回。
- 无效、暂停、到期或删除的链接返回统一 404；上游超时、超限、不可用或临时容量不足返回 503，不把错误页包装成配置。
- 失败时不默认返回过期缓存；保留上次成功正文用于后续条件请求。删除或改名后的 Gist 文件报错，不自动选其他文件。
- 导入和拉取仅接受固定 Gist 域名，逐跳核对 HTTPS、路径、来源身份，不提供任意 URL 转发或用户自带代理。
- 原始 Gist 若仍可访问，知道旧地址的人仍可绕过网站；Secret Gist 并非真正访问控制。迁移旧入口和更换已泄露的节点凭据不由本程序自动执行。
